CICD Step By Step:
----------------------------------
Step_1: Installation & Configuration of Jenkins

Installation of Jenkins:
-> We have to Ensure that our software packages are up to date on our instance by uing the following command:
	[] yum update –y
-> We have to Add the Jenkins repo using the following command:
	[] wget -O /etc/yum.repos.d/jenkins.repo https://pkg.jenkins.io/rpm-stable/jenkins.repo
-> To Import a key file from Jenkins-CI to enable installation from the package:
	[] rpm --import https://pkg.jenkins.io/rpm-stable/jenkins.io-2026.key
-> To upgrade
	[] yum upgrade
-> To Install Java 
	[] yum install java-21-amazon-corretto -y
-> To Install Jenkins
	[] yum install jenkins -y
-> To Enable the Jenkins service to start at boot:
	[] systemctl enable jenkins
-> To Start Jenkins as a service:
	[] systemctl start jenkins
-> We can check the status of the Jenkins service using the command:
	[] systemctl status Jenkins

Configuring Jenkins:
-> Connect to http://<your_server_public_DNS>:8080 from the browser. We will be able to access Jenkins through its management interface:
	[] http://PublicIP:8080
-> As prompted, enter the password found in /var/lib/jenkins/secrets/initialAdminPassword.
We have to use the following command to display this password:
	[] cat /var/lib/jenkins/secrets/initialAdminPassword
-> The Jenkins installation script directs us to the Customize Jenkins page. We have to Click on Install suggested plugins.
-> Once the installation is complete, the Create First Admin User will open. We have to enter our information, and then select Save and Continue.
-> On the left-hand side, we have to select Manage Jenkins, and then we have to select Plugins.
-> Select the Available Plugins, and then enter Amazon EC2 plugin at the top right.
-> Select the checkbox next to Amazon EC2 plugin, and then select Install without restart.
-> Once the installation is done, select Back to Dashboard.
-> Select Configure a cloud if there are no existing nodes or clouds.
-> If we already have other nodes or clouds set up, select Manage Jenkins.
	a. After navigating to Manage Jenkins, select Configure Nodes and Clouds from the left hand side of the page.
	b. From here, select Configure Clouds.
-> Select Add a new cloud, and select Amazon EC2. A collection of new fields appears.
-> Click Add under Amazon EC2 Credentials
	a. From the Jenkins Credentials Provider, select AWS Credentials as the Kind.
	b. Scroll down and enter in the IAM User programmatic access keys with permissions to launch EC2 instances and select Add.
	c. Scroll down to select your region using the drop-down, and select Add for the EC2 Key Pair’s Private Key.
	d. From the Jenkins Credentials Provider, select SSH Username with private key as the Kind and set the Username to ec2-user.
	e. Scroll down and select Enter Directly under Private Key, then select Add.
	f. Open the private key pair you created in the creating a key pair step and paste in the contents from "-----BEGIN RSA PRIVATE KEY-----" to "-----END RSA PRIVATE KEY-----". Select Add when completed.
	g. Scroll down to "Test Connection" and ensure it states "Success". Select Save when done
-> We are now ready to use EC2 instances as Jenkins agents.

Step_3: Nexus Integration

Installing nexus:
	[] yum install java-1.8.0-openjdk-devel -y
	[] cd /opt
	[] wget http://download.sonatype.com/nexus/3/nexus-3.15.2-01-unix.tar.gz
	[] tar -zxvf nexus-3.15.2-01-unix.tar.gz
	[] mv /opt/nexus-3.15.2-01 /opt/nexus
-> As a good security practice, Nexus is not advised to run nexus service as a root user, so create a new user called nexus and grant sudo access to manage nexus services as follows.
	[] useradd nexus
-> Give the sudo access to nexus user
	[] visudo
	[] nexus ALL=(ALL) NOPASSWD: ALL
-> Change the owner and group permissions to /opt/nexus and /opt/sonatype-work directories.
	[] chown -R nexus:nexus /opt/nexus
	[] chown -R nexus:nexus /opt/sonatype-work
	[] chmod -R 775 /opt/nexus
	[] chmod -R 775 /opt/sonatype-work
-> Open /opt/nexus/bin/nexus.rc file and  uncomment run_as_user parameter and set as nexus user.
	[] vi /opt/nexus/bin/nexus.rc
	[] run_as_user="nexus"
-> Create nexus as a service
	[] ln -s /opt/nexus/bin/nexus /etc/init.d/nexus
-> Switch as a nexus user and start the nexus service as follows.
	[] sudo su - nexus
-> Enable the nexus services
	[] sudo systemctl enable nexus
-> Start the nexus service
	[] sudo systemctl start nexus
-> Hit the browser with = PubIP:8081/nexus
-> Login with user name as admin and password is admin123
-> Click on Repository > Click on Create Repository > Choose Maven2(Hosted).
-> Give the Name, Version policy (Mixed), Deployment Policy (Redeploy) > Click on Create

-> Go to Build > Click on build steps > Invoke top-level Maven targets > Provide the Maven version and set the goal as install -DskipTests

Tomcat integration:

Tomcat Installation:
	[] yum install java-1.8.0-openjdk-devel -y
	[] wget https://dlcdn.apache.org/tomcat/tomcat-9/v9.0.120/bin/apache-tomcat-9.0.120.tar.gz

https://dlcdn.apache.org/tomcat/tomcat-9/v9.0.120/bin/apache-tomcat-9.0.120.tar.gz

	[] tar -xvzf apache-tomcat-9.0.120.tar.gz
	[] cd apache-tomcat-9.0.120
	[] ls -latr
	[] cd conf/
-> Add below lines in the bottom of tomcat-users.xml file
	[] vi tomcat-users.xml
	<role rolename="manager-gui"/>
<role rolename="manager-script"/>
<user username="tomcat" password="ChangeThisToAStrongPassword!" roles="manager-gui,manager-script"/>
-> After adding above lines save the file
-> Navigate to apache-tomcat-9.0.120/webapps/manager/META-INF
	[] vi context.xml
-> Comment the below line
	<!--
	  <Valve className="org.apache.catalina.valves.RemoteAddrValve"
	        allow="127\.\d+\.\d+\.\d+|::1|0:0:0:0:0:0:0:1" />
	-->
-> Save the file and exit.
-> Start the tomcat 
	[] cd apache-tomcat-9.0.120/bin
	[] ./startup.sh
	[] tail -f ../logs/catalina.out
	[] curl -I http://localhost:8080 > Verify
-> Here tomcat will start 
-> Hit the browser with PubIP:8080
-> Click on manager app and login with credentials.

We have to integrate CI/CD in one go, so that jobs run one after another. For that, we need to install a plugin. Steps:

1. Go to Manage Jenkins > Plugins > Install Build Pipeline Plugin
2. Go to Dashboard > New View > Give a name > Select Build Pipeline View > Click Create
3. Give a name > In Pipeline Flow, select Initial Job as GIT_Integration
4. Go to GIT_Integration job > Post-Build Actions > Select Build other projects > Enter the next project's name (e.g., Maven_Integration)
5. Go to Maven_Integration job > Build Triggers > Select Build after other projects are built > Enter the project to watch (GIT_Integration) > In Post-Build Actions, select Build other projects > Enter the next project's name (Nexus_Integration)
6. Repeat the same pattern for Nexus_Integration (trigger from Maven_Integration, then post-build trigger Tomcat_Integration) and for Tomcat_Integration (trigger from Nexus_Integration)
7. Go to the Pipeline View and click Run to trigger the entire chain.

SonarQube Integration & Configuration:

Prerequisites:
-> Need an EC2 instance (min t2.small)
-> Install dependencies: JAVA
	[] apt-get update   
  [] apt-get install java-21-amazon-corretto -y   

Install & Setup Postgres Database for SonarQube:
-> Install Postgres database   
	[] sudo sh -c 'echo "deb http://apt.postgresql.org/pub/repos/apt $(lsb_release -cs)-pgdg main" > /etc/apt/sources.list.d/pgdg.list'  
	[] wget --quiet -O - https://www.postgresql.org/media/keys/ACCC4CF8.asc | sudo apt-key add -
	[] apt-get update
	[] apt-get -y install PostgreSQL
-> Set a password and connect to database (setting password as "admin" password)
	[] sudo passwd postgres > Change default for postgres user using
  [] su - postgres > Switch to postgres user from your cli
-> Create a database user and database for sonarqube 
	[] createuser sonar
  [] psql > login to the postgresql database dashboard
  	> ALTER USER sonar WITH ENCRYPTED PASSWORD 'admin';
  	> CREATE DATABASE sonarqube OWNER sonar;
  	> GRANT ALL PRIVILEGES ON DATABASE sonarqube to sonar;
	[] \q > Once we are done we will quit the postgresql dashboard
	[] exit > Switch back to the initial user
-> Restart postgres database to take latest changes effect 
  [] systemctl restart postgresql 
  [] systemctl status postgresql
	[] apt install net-tools
-> Added below entries in '/etc/sysctl.conf'
	[] cd /etc > vi sysctl.conf
  	> vm.max_map_count=524288
  	> fs.file-max=131072
  	> ulimit -n 131072
  	> ulimit -u 8192
  [] Esc > :wq!
-> Add below entries in '/etc/security/limits.conf'  
	[] cd /etc/security > vi limits.conf
	  > sonarqube   -   nofile   131072
  	> sonarqube   -   nproc    8192
  [] Esc > :wq!
-> reboot the server 
  [] init 6

SonarQube Setup:
-> We will install these commands incase if not available on the machine
	[] sudo apt update
	[] sudo apt install wget unzip -y
-> Download [soarnqube](https://www.sonarqube.org/downloads/) and extract it.   
	[] wget https://binaries.sonarsource.com/Distribution/sonarqube/sonarqube-8.9.2.46101.zip
  [] unzip sonarqube-8.9.2.46101.zip

Haven done that conguration above we can modify and make changes to sonarqube config file:
-> Navigate to the directory  
	[] nano /opt/sonarqube/conf/sonar.properties
-> Update sonar.properties with below information 
	  #sonar.jdbc.username=sonar
  	#sonar.jdbc.password="Set Your Password"
  	#sonar.jdbc.url=jdbc:postgresql://localhost/sonarqube
  	#sonar.search.javaOpts=-Xmx512m -Xms512m -XX:MaxDirectMemorySize=256m -XX:+HeapDumpOnOutOfMemoryError
  [] Ctrl + C > Shift + A 

Setup Systemd Service:
-> Create a '/etc/systemd/system/sonar.service' file start sonarqube service at the boot time 
 	[] cd /etc/systemd/system
	[] vi sonar.service  
	    [Unit]
  	  Description=SonarQube service
  	  After=syslog.target network.target

  	  [Service]
    	Type=forking
  	  User=sonar
  	  Group=sonar
  	  PermissionsStartOnly=true
  	  ExecStart=/opt/sonarqube/bin/linux-x86-64/sonar.sh start 
    	ExecStop=/opt/sonarqube/bin/linux-x86-64/sonar.sh stop
    	StandardOutput=syslog
    	LimitNOFILE=65536
    	LimitNPROC=4096
    	TimeoutStartSec=5
    	Restart=always

    	[Install]
  	  WantedBy=multi-user.target
	[] Esc > :wq!
-> Add sonar user and grant ownership to /opt/sonarqube directory 
 	[] useradd -d /opt/sonarqube sonar
 	[] chown -R sonar:sonar
-> Reload the demon and start sonarqube service 
 	[] systemctl daemon-reload 
 	[] systemctl start sonarqube.service
